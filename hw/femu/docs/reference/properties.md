# Device property reference

Every property of the FEMU devices, as the binary reports it. `./qemu-system-x86_64 -device femu,help` prints the same descriptions at the terminal. Properties are set on the command line, for example `-device femu,femu_mode=1,devsz_mb=4096`, and only before the device is realized; the QOM properties that can be read or changed while the guest runs are in [runtime-properties.md](runtime-properties.md).

Mode names follow `femu_mode`: OCSSD (0), bbssd (1, black box), NoSSD (2), ZNS (3), CSD (4) and KV (5). CSD builds the bbssd FTL, so the bbssd geometry, timing and FTL properties apply to it; KV uses only the bbssd geometry and NAND timing. Each description names the modes it applies to.

Devices:

- [`femu`: NVMe controller](#femu-nvme-controller)
- [`femu-subsys`: NVMe subsystem](#femu-subsys-nvme-subsystem)
- [`femu-cxl-ssd`: CXL Type-3 SSD](#femu-cxl-ssd-cxl-type-3-ssd)
- [Test-only properties](#test-only-properties)
- [Environment variables](#environment-variables)

## `femu`: NVMe controller

`-device femu` has 336 properties of its own and 4 QOM properties listed in [runtime-properties.md](runtime-properties.md).

### Mode, capacity and namespaces

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `femu_mode` | `uint8` | `2` | Emulated SSD type: 0 OCSSD (Open-Channel), 1 bbssd (black-box FTL), 2 NoSSD (no media timing), 3 ZNS, 4 CSD (computational), 5 KV; other values fail realize |
| `mode` | `str` | unset | the emulated SSD type by name: ocssd, bbssd, nossd, zns (or znssd), csd or kv (or kvssd); it sets femu_mode, and a femu_mode other than 2 must name the same type; unset (default) leaves femu_mode |
| `devsz_mb` | `uint32` | `1024` | Size of the host memory backend in MiB, split across namespaces unless namespace_sizes is set; bbssd with op_pcent sizes from the NAND geometry instead |
| `mem_limit` | `size` | `0` | Startup memory limit in bytes (QEMU size syntax): realize refuses the device before an allocation that passes it; counts the retained bytes query-femu-memory reports, not memory that I/O adds later; a lazy FTL table counts in full, which is what is resident under -overcommit mem-lock=on; not with ZNS, ocssd or cxl_ssd; 0 (default) sets no limit |
| `namespaces` | `uint32` | `1` | Number of namespaces created at boot, 1 to 256; OCSSD supports only 1, and FDP more than 1 only when all are bbssd or all nossd |
| `namespace_sizes` | `str` | unset | Comma-separated size in bytes of each namespace (QEMU size syntax such as 4G,2G), one non-empty entry per namespace, summing to at most the backend; unset splits the backend evenly |
| `namespace_modes` | `str` | unset | Comma-separated mode of each namespace from nossd, bbssd, znssd (or zns), ocssd, csd and kvssd (or kv), one entry per namespace; unset gives every namespace femu_mode |
| `namespace_phls` | `str` | unset | FDP placement handle list of each namespace: comma-separated entries, one per namespace, each a ':'-separated list of reclaim unit handle IDs such as 0:1,,2 (placement handle i selects entry i); needs fdp=on, and unset gives every namespace every handle |
| `op_pcent` | `uint32` | `0` | Over-provisioning in percent for bbssd: back the device with the full NAND capacity and expose capacity/(1 + op_pcent/100); 0 keeps devsz_mb sizing, not with cxl_ssd |
| `subsys` | `link<femu-subsys>` | unset | ID of a femu-subsys device to join, created before this controller; needed for FDP, shared namespaces and the Endurance Group log |
| `cxl_ssd` | `link<femu-cxl-ssd>` | unset | ID of a femu-cxl-ssd, listed before this controller, whose memory and FTL this bbssd controller serves as its one namespace |
| `pel_file` | `str` | unset | Host file that keeps the Persistent Event Log and power cycle count across runs, created if missing; a corrupt or incompatible file fails realize, and so does a name that ends in .lock |
| `persist_file` | `str` | unset | bbssd, NoSSD: host file that keeps the data and the deallocated and uncorrectable blocks across runs; realize loads it, unplug or the end of QEMU saves it (not with persist_load_only). A file of another mode, size, namespace layout or LBA format fails realize, and FILE.lock keeps a second user out (readers of persist_load_only share it). FILE.lock is empty and stays after unplug. Format NVM keeps the LBA format. The FTL state is kept only with persist_ftl. Not with namespace_modes, ns_mgmt, shared namespaces, cxl_ssd, metadata or sanitize_ms |
| `persist_ftl` | `bool` | `off` | bbssd with mapping=page: persist_file keeps the FTL state too (mapping, page and block state, lines, write pointer, counters, and the wear, retention, read reclaim, levelling and RBER state), so a restarted drive continues as it was; a file of other geometry, mapping, GC, NAND timing or aging properties fails realize, and so does a file without FTL state on a device with an aging model. Not with FDP or the FTL features whose state it does not keep (realize names the property); off (default) |
| `persist_load_only` | `bool` | `off` | with persist_file: the file is a checkpoint that realize loads and nothing saves, so each run starts from it. The file must exist. FILE.lock is made if missing and held shared, so other devices and QEMU processes can load the same file, and a device that saves it cannot start. With no FILE.lock in a read-only directory of a local file system the device holds the file itself, shared, and warns. The guest still writes the device; femu-save-data can write another file. off (default) |
| `io_trace` | `str` | unset | host file for an I/O trace: one CSV line per completed I/O command (t_submit_ns, t_cqe_ns, sqid, cid, nsid, opcode, slba, nlb, status), in every mode; the file must not exist; unset (default) is off |
| `events_file` | `str` | unset | host file of timed actions, read at realize: lines '<ms> <action>' or '<ms>+<window>~<seed> <action>', the action ana=<group>:<state> (state 1 to 3, needs ana=on), power-loss (needs power_loss=on) or slow=<ch>:<lun>:<pct> (needs die_slow=on); times count from the first enable and survive resets; see query-femu-events; bbssd: lines '@<op>[,ns=N][,lba=A-B]#N <action>' or '@...%PPM~SEED <action>' select commands, with no effect yet; not with csd_pause; unset (default) is off |
| `events_log` | `str` | unset | with command lines in events_file: host file that gets one JSON line per fault record, appended by a thread of its own; the ring then keeps the records not yet written, and a full ring drops new records and counts them; a write error stops the file, not the run; only a regular file, /dev/null or /dev/full; refused: a file another femu file uses, also by a hard link, and a file that ends in a partial line; unset (default) keeps the last events_max_faults records for query-femu-events |
| `events_max_faults` | `uint32` | `4096` | slots of the fault record ring of events_file command lines, 1 to 65536 entries of 72 bytes; allocated only with a command line; 4096 (default) |
| `die_slow` | `bool` | `off` | bbssd, CSD: on makes the array time of each LUN settable at run time with the die-slow property or a slow= action of events_file, for a die that turns slow; one namespace only, not with ns_mgmt, namespace_modes, subsys or cxl_ssd; query-femu lists slow LUNs; off (default) adds nothing to the media path |
| `die_stats` | `bool` | `off` | bbssd: count, per LUN, the array bookings, the ones that waited for a busy LUN, the wait and the array time, for query-femu kind dies; not with plane_reads, pe_suspend, read priority, cache reads or bus timing yet; off (default) adds nothing to the media path |
| `serial` | `str` | unset | No effect, kept for compatibility; Identify Controller reports a serial number FEMU generates. Setting it warns at realize |

## Environment variables

FEMU reads these variables from the environment of the QEMU process. They are
debugging and host-placement aids, not device configuration, so they have no
`-device` property. When QEMU runs under `sudo`, pass them through, for example
`sudo FEMU_EXP_LOG=1 ./run-blackbox.sh` or `sudo -E`.

| Variable | Read by | Effect |
| --- | --- | --- |
| `FEMU_MBE_INTERLEAVE` | memory backend, every mode (`hw/femu/backend/dram.c`) | `on` interleaves the backend memory across NUMA nodes 0 and 1; `0` or `1` binds it to that node. Other values are ignored with a message. Unset leaves the host default policy. |
| `FEMU_FDP_DEBUG` | bbssd FTL (`hw/femu/bbssd/ftl.c`) | Any value, even empty, prints FDP placement and reclaim traces to stderr. |
| `FEMU_EXP_LOG` | bbssd FTL (`hw/femu/bbssd/ftl-exp.c`) | A non-empty value prints `[EXP]` lines to stderr that trace the writes, overwrites, deallocations, garbage collection moves and erases of pages whose data contains `FEMU_SECRET`; without `FEMU_SECRET` nothing is traced. |
| `FEMU_SECRET` | bbssd FTL (`hw/femu/bbssd/ftl-exp.c`) | A non-empty marker string that selects the pages `FEMU_EXP_LOG` traces. |
| `FEMU_DUMP_LPN` | bbssd FTL (`hw/femu/bbssd/ftl-exp.c`) | A logical page number (decimal or 0x hex) whose backend page is hex-dumped to stderr on every read not served from the write buffer, independent of `FEMU_EXP_LOG`. |
| `FEMU_KV_SELFTEST` | KV FTL (`hw/femu/kvssd/kvssd-ftl.c`) | Any value runs the KV FTL self-test once at realize and logs the result. |
| `FEMU_KV_CHECK` | KV FTL (`hw/femu/kvssd/kvssd-ftl.c`) | Any value checks the owner of every NAND page after each value GC and every 64 commands, and stops QEMU on a broken invariant. The qtests set it. It is slow on a large device. |
